Add opt-in session-start gating to the 24/7 `issuer-price-247` endpoint (env-gated via `ISSUER_247_SESSION_START_GATING_ENABLED`, default off): reports whose `lastSeenTimestampNs` predates the start of the session their `marketStatus` declares are rejected with 503 `PRE_SESSION(...)`; WEEKEND/closed-span reports gate against the end of the last trading phase before the gap. Indeterminate sessions (UNKNOWN/unmapped `marketStatus` or an unresolvable session start) fail closed with 503 `Session start unknown` — there is no fail-open toggle (ADR-0007). Also flattens the hard-coded fallback session schedule to a single per-market entry with per-phase end times (24/5 behavior unchanged), parses the tradinghours `market-session` `endTime` passthrough, and routes both gating paths' tradinghours schedule fetches through a shared in-process stale-while-revalidate cache (`TRADINGHOURS_SESSION_CACHE_TTL_MS`, default 60s) whose blocking fetches are deduped per key and, after a failure, suppressed for `TRADINGHOURS_SESSION_CACHE_FAILURE_BACKOFF_MS` (default 5s) so an outage cannot stampede tradinghours or add the fetch timeout to every gated request. A missing or empty `endTime` is treated as "no end" rather than a malformed schedule. See `docs/issuer-247-session-start-gating-tdd.md` and `docs/adr/0007-247-session-start-gating-weekend-and-fail-closed.md`.
