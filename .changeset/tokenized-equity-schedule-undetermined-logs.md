Alert-facing logging for session-start gating schedule failures (24/5 and 24/7): a distinct error line (`Market schedule undetermined: …`) now discriminates the two no-schedule-tier causes — an invalid market session name (unknown `sessionMarketType`, logged up front since tradinghours cannot resolve the type either) vs. no fallback schedule entry for the market (logged only when the tradinghours fetch also fails or cannot run — a healthy tradinghours is itself a schedule tier, so the line stays quiet during healthy operation) — which previously surfaced only as an unattributed 503 `Session start unknown`. A malformed tradinghours schedule (unparseable phase `time`/`endTime`) is now rejected whole and lands in the existing `TradingHoursEA request failed` line instead of silently propagating NaN timestamps. The 24/7 gate gains the 24/5 fallback-activation warn (fetched schedule has no transition opening the report's session). The `TradingHoursEA request failed` line is now throttled to one per minute per market/type, so a sustained outage stays visible without re-logging on every gated request (the cache's failure backoff suppresses the upstream fetch, not the caller's log). No gating behavior change.
